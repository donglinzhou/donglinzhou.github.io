语义 ID 如何连接 LLM 与序列推荐

一句话：语义 ID 不是简单把商品标题喂给 LLM，而是把商品语义、共现关系、地理约束和协同信号压缩成推荐模型可学习、可检索、可组合的离散表示。

1. 为什么需要新的 Item 表征

传统推荐模型擅长从用户交互中学习 ID 协同信号：谁和谁共同点击、购买、观看，往往直接反映短期兴趣和转化意图。但纯 ID 方法面对冷启动商品会很吃力，因为新商品缺少足够交互，ID embedding 无法充分训练。

LLM 带来了另一种知识来源。商品标题、类目、POI 名称、地址和评论经过语言模型编码后可以表达丰富语义。即使一个新商品没有交互，也可能通过内容语义找到相近商品。但 LLM embedding 不是银弹：它未必理解平台内协同关系，也未必充分编码地理距离、供给密度和转化目标。

2. 三条语义 ID 技术路线

路线 A：RQ-VAE / 残差量化

先学习连续内容向量，再通过残差量化得到层级 token。粗粒度 token 表达大类或高层语义，细粒度 token 表达局部差异。它适合生成式检索，但要面对量化误差和 token 稳定性问题。

路线 B：LLM embedding 对齐

使用 LLM 对标题、类目、品牌、地理位置等信息编码，再通过对比学习或蒸馏，把业务 item embedding 对齐到 LLM 语义空间。本地生活场景还需要额外注入商圈、地理距离和供给密度。

路线 C：ID-Content 模态对齐

把 ID、文本、图像视作不同模态，通过自监督任务让它们在共享空间中靠近，再进行序列偏好学习。SICSRec 的核心可以概括为：先解决内容语义和交互 ID 的对齐，再解决用户行为序列建模。

3. 为什么 Semantic 与 ID 必须联合

在 LLM-based Semantic and ID Representations for Sequential Recommendation 中，关键不是用 LLM 表征替换 ID，而是让两者互补。语义表征提供跨商品迁移能力，ID 表征保留平台内精确协同模式。

Gated Attention 可以根据上下文动态决定“更相信语义还是更相信行为”；MoE 则让不同样本或兴趣模式使用不同组合策略。冷启商品需要语义侧先验，高交互商品则可以更多依赖 ID 协同。

4. 工业落地的三个启发

  1. 语义 ID 必须业务化。本地生活商品不仅有标题语义，还有商圈、地理密度、商家供给和履约约束。
  2. 样本构造比模型名字更关键。基于地理密度构造正负样本，会直接影响 embedding 对齐是否符合本地生活决策。
  3. 能否进入精排特征体系决定落地价值。研究想法需要稳定、低延迟、可训练、能接入 MMoE 等现有模型。

5. 仍然开放的问题

  • 如何评估一个语义 ID tokenizer 的好坏，而不仅看最终推荐指标？
  • 语义 ID 的层级结构是否可解释，能否对应类目、商圈、价格带或消费场景？
  • 当商品改名、搬迁、上下架时，如何更新 token 并避免历史序列语义漂移？
  • LLM 语义与协同信号冲突时，模型如何动态加权？

本周结论

生成式推荐的关键不只是“把推荐改写成语言生成”，而是构造同时适合大模型和推荐目标的中间表示。语义 ID 正处在内容语义、协同过滤和工业推荐系统的交界处，也是我后续会持续追踪的方向。
