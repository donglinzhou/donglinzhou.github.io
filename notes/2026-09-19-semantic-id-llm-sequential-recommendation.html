语义 ID 如何连接 LLM 与序列推荐

2026-09-19Donglin ZhouLLM4Rec / Semantic ID / Sequential Recommendation
一句话：语义 ID 不是简单把商品标题喂给 LLM，而是把商品的语义、共现、地理和协同关系压缩成推荐模型可学习、可检索、可组合的离散表示；它需要与传统 ID 表征联合，而不是彼此替代。

1. 为什么推荐系统需要新的 Item 表征？

传统推荐模型擅长从用户交互中学习 ID 协同信号：谁和谁共同点击、购买、观看，往往直接反映短期兴趣和转化意图。但纯 ID 方法有两个天然问题：第一，冷启商品交互少，ID embedding 难以充分训练；第二，ID 本身是离散且无语义的，模型很难把“相似商品”的知识迁移到新商品。

LLM 带来了相反的优势。商品标题、类目、POI 名称、地址和用户评论经过语言模型编码后，可以表达丰富语义；一个新商品即使没有交互，也可能通过文本语义找到相近商品。但 LLM embedding 也不是银弹：它可能不理解真实业务中的协同关系，也未必充分编码地理距离、供给约束和转化目标。

2. 语义 ID 的核心想法

语义 ID 可以理解为：先把商品映射到一个语义空间，再通过量化、聚类或对齐方法生成一串短 token。它一方面保留内容语义，另一方面又像传统 ID 一样可以进入 Embedding Table、序列模型和精排网络。

我的理解：语义 ID 的价值在于“桥接两种统计规律”。内容语义来自大规模文本或多模态知识，协同信号来自平台内真实行为；前者负责泛化，后者负责决策。

3. 三条常见技术路线

路线 A：RQ-VAE / 残差量化

先学习连续内容向量，再通过残差量化得到层级 token。较粗粒度 token 表达大类或高层语义，较细粒度 token 表达局部差异。它的优点是压缩能力强，适合生成式检索；难点是量化误差和 token 稳定性。

路线 B：LLM embedding 对齐

使用 LLM 对商品标题、类目、品牌、地理位置等信息进行编码，再通过对比学习或蒸馏，把业务侧 item embedding 对齐到 LLM 语义空间。在本地生活场景，仅靠文本仍不够，因为“距离近”“同一商圈”“供给密度”这类信息并不总在名称中显式出现。

路线 C：ID-Content 模态对齐

这类方法把 ID、文本、图像等视作不同模态，通过自监督任务让它们在共享空间中靠近，再进行序列偏好学习。SICSRec 的思路正属于这一类：先做内容模态语义对齐，再进入二阶段序列推荐。

4. SIDSRec 为什么要同时保留 Semantic 与 ID？

在 LLM-based Semantic and ID Representations for Sequential Recommendation 中，关键不是用 LLM 表征替换 ID，而是让两者互补。语义表征提供跨商品迁移能力，ID 表征保留平台内精确协同模式。Gated Attention 可以根据上下文动态决定“更相信语义还是更相信行为”，MoE 则让不同样本或兴趣模式使用不同组合策略。

这对冷启动和热门商品的区别尤其重要：冷启商品需要语义侧提供先验；高交互商品则可以更多依赖 ID 协同。固定权重很难同时适配两类样本，因此动态融合是自然选择。

5. 从工业实习得到的三个启发

  • 语义 ID 必须业务化。本地生活商品不仅有标题语义，还有商圈、地理密度、商家供给和履约约束，生成 token 时要引入这些信号。
  • 样本构造比模型名字更关键。例如 POI 语义 ID 中，基于地理密度构造正负样本，会直接影响 embedding 对齐是否符合本地生活决策。
  • 能否进入精排特征体系决定落地价值。一个研究想法只有稳定、低延迟、可训练、能接入 MMoE 等现有模型，才可能产生线上收益。

6. 仍然开放的问题

  1. 如何评估一个语义 ID tokenizer 的好坏，而不仅看最终推荐指标？
  2. 语义 ID 的层级结构是否可解释，能否对应类目、商圈、价格带或消费场景？
  3. 当商品信息变化（改名、搬迁、上下架）时，如何更新 token 并避免历史序列语义漂移？
  4. LLM 语义与协同信号冲突时，模型应如何按用户、场景和商品生命周期动态加权？

本周结论

生成式推荐的关键不只是“把推荐改写成语言生成”，而是构造同时适合大模型和推荐目标的中间表示。语义 ID 正处在内容语义、协同过滤和工业推荐系统的交界处，也是我后续会持续追踪的方向。
